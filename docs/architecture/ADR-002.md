# ADR-002 — Azure Function as API and Database Boundary

## Status

Accepted

## Requirement Addressed

- REQ-AZ-007
- REQ-AZ-008
- REQ-AZ-009
- REQ-AZ-010
- REQ-AZ-SEC-002

## Decision

Use an Azure Function with an HTTP trigger as the only application boundary between browser JavaScript and Cosmos DB.

The function will be implemented in Python.

## Alternatives Considered

### Direct browser-to-Cosmos DB access

Rejected because the approved requirements explicitly prohibit it.

### Additional backend service

Rejected because the challenge requires Azure Functions and the additional service would increase cost and scope.

### Static-only implementation

Rejected because the visitor counter requires server-side persistence.

## Trade-offs

Advantages:

- Protects database access.
- Demonstrates serverless backend development.
- Keeps the frontend simple.
- Fits the cost objective.

Trade-offs:

- Adds an API dependency.
- Introduces function cold-start/runtime failure modes.
- Requires API contract definition.

## Consequences

The API becomes a critical security and application boundary.

The browser receives only the approved counter response.
