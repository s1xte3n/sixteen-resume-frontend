# ADR-005 — Secure CI/CD Authentication and Least Privilege

## Status

Accepted

## Requirement Addressed

- REQ-AZ-SEC-001
- REQ-AZ-SEC-003
- REQ-AZ-013
- REQ-AZ-014

## Decision

CI/CD will authenticate to Azure using GitHub Actions OpenID Connect (OIDC) workload identity federation with a dedicated Microsoft Entra user-assigned managed identity. No client secret or certificate is stored for GitHub-to-Azure authentication.

The frontend deployment identity will be scoped to the required Storage data-plane publication/cache operations. The backend deployment identity will be scoped to the resource group/resources required to validate and deploy the ARM-defined Function/Cosmos/Storage/delivery resources.

The Azure Function runtime will use its managed identity with Azure Cosmos DB for Table native data-plane RBAC, scoped to the minimum required table/account scope. Key-based Cosmos authentication is not the default implementation path.

Deployment permissions must be limited to the resources and operations required by each workflow.

## Alternatives Considered

### Long-lived Azure client secrets

Rejected as the default because OIDC removes the need for a stored long-lived credential.

Rejected.

### Hardcoded Azure credentials

Rejected.

### Credentials committed to GitHub repository

Rejected.

### One unrestricted subscription-level identity

Rejected because it violates least privilege.

## Trade-offs

Advantages:

- Prevents credential leakage through source.
- Limits blast radius.
- Supports automated deployment.

Trade-offs:

- Requires initial identity configuration.
- Initial Azure/GitHub federation and RBAC configuration must be created and validated.
- The selected roles must be tested for least privilege before production.

## Consequences

The final workflow must document:

- GitHub Actions OIDC authentication.
- Entra user-assigned managed identity used by each workflow.
- Resource scopes and Azure RBAC assignments.
- Function managed identity and Cosmos DB for Table data-plane role assignment.
- Secret handling, including the absence of long-lived Azure deployment secrets.
