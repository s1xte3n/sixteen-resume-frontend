# ADR-005 — Secure CI/CD Authentication and Least Privilege

## Status

Accepted in principle

## Requirement Addressed

- REQ-AZ-SEC-001
- REQ-AZ-SEC-003
- REQ-AZ-013
- REQ-AZ-014

## Decision

CI/CD must authenticate to Azure using secure, non-committed credentials or workload identity mechanisms supported by the final GitHub/Azure configuration.

Deployment permissions must be limited to the resources and operations required by each workflow.

## Alternatives Considered

### Hardcoded Azure credentials

Rejected.

### Credentials committed to GitHub repository

Rejected.

### One unrestricted subscription-level identity

Rejected because it violates least privilege.

## Trade-offs

Advantages:

- Prevents credential leakage through source.
- Limits blast radius.
- Supports automated deployment.

Trade-offs:

- Requires initial identity configuration.
- Exact authentication mechanism must be validated during implementation.

## Consequences

The final workflow must document:

- Authentication mechanism.
- Azure identity.
- Scope.
- Permissions.
- Secret handling.
