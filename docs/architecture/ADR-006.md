# ADR-006 — HTTPS/CDN Delivery Architecture

## Status

Accepted — capability architecture resolved; service selection remains implementation validation

## Requirement Addressed

- REQ-AZ-005
- REQ-AZ-006
- REQ-AZ-014
- REQ-AZ-015
- REQ-AZ-SEC-004

## Decision

Use an **Azure-managed HTTPS/CDN delivery layer** in front of the Azure Storage static website.

The exact Azure edge service/configuration is intentionally an implementation choice rather than an architecture lock. It must be selected only after validating current availability/lifecycle, HTTPS and certificate support, public-hostname compatibility, Azure Storage Static Website origin compatibility, ARM/IaC support, current pricing, and compliance with the **R100/month recurring Azure/cloud cost ceiling**.

## OR-004 Resolution

OR-004 is resolved at the architecture level. The frozen acceptance conditions are: HTTPS support; certificate management; public-hostname resolution to the edge endpoint; Azure Storage Static Website as origin; IaC representation where applicable; recurring Azure/cloud cost <= R100/month; and service availability/suitability for the required deployment architecture.

The exact Azure edge service remains an implementation selection governed by these conditions.

## Current Direction

The architecture requires an Azure-managed delivery layer conceptually:

```text
Public Hostname
      |
      v
Azure-managed HTTPS/CDN delivery layer
      |
      +-- HTTPS
      +-- CDN / edge delivery
      |
      v
Azure Storage Static Website
```

The public hostname remains the approved FreeDNS hosted hostname/subdomain interpretation recorded by OR-002.

The delivery layer is intentionally represented by required capabilities rather than a fixed Azure SKU. Implementation must validate the selected service against the frozen OR-004 conditions before production deployment.

## Service Validation

No specific Azure edge service is currently selected as the final implementation service.

Candidate services must be evaluated against the requirements and the **R100/month** total recurring Azure/cloud ceiling. Azure Front Door Standard may be evaluated as a candidate during implementation validation, but it is **not an approved implementation decision**.

## HTTPS and Certificate Decision

The selected delivery architecture must provide HTTPS for the approved public hostname.

Where an Azure-managed certificate is supported by the selected service and hostname model, it is preferred to avoid unnecessary certificate-management infrastructure.

Production acceptance requires:

1. The selected delivery service is explicitly validated and documented.
2. The FreeDNS hostname is successfully associated with the delivery endpoint.
3. HTTPS is active.
4. HTTP-to-HTTPS redirection is configured where required.
5. The public hostname serves the resume successfully over HTTPS.
6. The configuration is reproducible through source-controlled infrastructure where applicable.

## Cost Decision

The approved recurring Azure/cloud cost ceiling is **R100/month**.

- **R0/month** is the preferred target where viable.
- **R0** one-time project infrastructure/domain cost is required by the MVP.
- Paid domain registration is excluded by OR-002.
- Any charge above the approved limits requires explicit Project Owner approval before deployment.

The ceiling is a project budget constraint, not a billing guarantee. Current pricing and projected billing must be validated before production deployment.

Cost validation must include the complete MVP configuration: Storage, Functions, Cosmos DB, the selected HTTPS/CDN delivery service, requests, data transfer, and other attributable Azure charges.

If a candidate delivery service cannot fit the **R100/month** ceiling with the rest of the required resources, it must not be selected.

## Alternatives

No delivery service is marked as the final selected alternative until OR-004 validation is complete.

Candidates must be evaluated consistently for:

- Azure-managed HTTPS.
- CDN/edge delivery.
- FreeDNS hostname compatibility.
- Azure Storage static website origin.
- ARM/IaC support.
- R100/month total recurring ceiling.
- Operational simplicity appropriate to the MVP.

## Decision Criteria

The final delivery architecture must:

- Provide public HTTPS.
- Integrate with Azure Storage.
- Support the approved FreeDNS hostname.
- Provide the required CDN/edge delivery behavior.
- Fit the approved **R100/month recurring Azure/cloud cost ceiling**.
- Be representable through source-controlled infrastructure where applicable.
- Have current service availability/lifecycle evidence.
- Have production acceptance evidence before the architecture is frozen.

## Consequence

Until the implementation validation gate is completed:

- The exact deployed edge service is **not yet selected** and must pass the frozen OR-004 validation conditions.
- Azure Front Door Standard is **not** an architecture commitment.
- Delivery implementation may become service-specific only after the selected service passes the frozen acceptance conditions.
- Cost estimates use the **R100/month** ceiling.
- Production delivery acceptance requires implementation evidence satisfying the resolved OR-004 capability conditions and the R100/month ceiling.

## Freeze Gate

This ADR unblocks implementation at the capability level. Before production deployment, record the selected service/SKU, current availability evidence, hostname/DNS evidence, HTTPS/certificate evidence, Azure Storage origin evidence, IaC evidence, and complete MVP cost evidence.

A candidate service must not be selected if it causes the complete MVP to exceed R100/month recurring Azure/cloud cost. Current pricing must be revalidated at implementation time.
