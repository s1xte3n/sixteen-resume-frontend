# ADR-006 — HTTPS/CDN Delivery Architecture

## Status

Accepted

## Requirement Addressed

- REQ-AZ-005
- REQ-AZ-006
- REQ-AZ-014
- REQ-AZ-015
- REQ-AZ-SEC-004

## Decision

Use **Azure Front Door Standard** as the managed HTTPS/CDN delivery layer in front of the Azure Storage static website.

- Azure Storage static website hosting.
- HTTPS.
- CDN/delivery capability.
- Public hostname.
- R0/month preferred target; USD $40/month recurring Azure/cloud cost is the hard MVP ceiling.

The exact Azure service configuration has not yet been validated against current service availability and pricing.

## Current Direction

Use an Azure-managed delivery/CDN layer in front of Azure Storage.

Conceptually:

```text
Public Hostname
      |
      v
FreeDNS / afraid.org hosted hostname
      |
      v
Azure Front Door Standard
      |
      +-- HTTPS with Azure-managed TLS certificate
      |
      +-- CDN / edge delivery
      |
      v
Azure Storage Static Website
```

The public hostname remains the approved FreeDNS hosted hostname/subdomain interpretation recorded by OR-002. No paid domain registration is required.

## Service Validation

Azure Front Door Standard is the selected delivery service because the current Azure service provides:

- Static and dynamic content delivery.
- SSL/TLS offload.
- Domain and certificate management.
- CDN/edge delivery.
- ARM-representable resources.
- Azure-managed TLS certificates for custom domains.

Azure Front Door Classic is not selected because Microsoft states that Front Door Classic retires on **31 March 2027** and no longer supports new domain onboarding or managed certificates. The project should therefore not introduce Classic resources.

## HTTPS and Certificate Decision

Use an **Azure-managed TLS certificate** on the Front Door custom domain.

The project will not introduce Azure Key Vault solely for this certificate because the managed certificate avoids that additional resource and its associated cost/operational burden.

HTTPS acceptance requires:

1. The FreeDNS hostname is onboarded as the Front Door custom domain.
2. Domain ownership/validation succeeds using the required DNS records.
3. Azure-managed HTTPS is enabled.
4. HTTP traffic is redirected to HTTPS.
5. The public hostname serves the resume successfully over HTTPS.

## Cost Decision

The project adopts the following numeric cost ceiling for the Azure deployment:

- **Recurring Azure ceiling: USD $40/month.**
- **One-time project infrastructure/domain cost: USD $0 required by the MVP.**
- Paid domain registration is excluded by OR-002.
- Any recurring or one-time charge that would exceed these limits requires explicit Project Owner approval before deployment.

Microsoft's current published Azure Front Door pricing lists a **$35/month Standard base fee**, billed hourly, plus usage-based data-transfer and request charges. For this low-traffic personal resume workload, the remaining **$5/month** is the allowed budget for Storage, Functions, Cosmos DB, and Front Door usage charges. Actual usage must be monitored and kept within the $40/month ceiling.

This is a project budget ceiling, not a guarantee of Azure billing. Azure pricing is region/usage/program dependent, and the project must verify the live subscription pricing before production deployment.

## Alternatives

### Azure Front Door Premium

Rejected for the MVP because its current published base fee is substantially higher than Standard and the project does not require Premium-only capabilities such as integrated WAF/Private Link for this resume workload.

### Azure Front Door Classic

Rejected because Microsoft has announced retirement on 31 March 2027 and the service no longer supports new domain onboarding or managed certificates.

### Direct Azure Storage HTTPS endpoint

Rejected because the project requires a CDN/delivery layer and public-hostname HTTPS architecture.

### Additional WAF/CDN services

Rejected because they add cost and infrastructure without being required by the approved MVP.

## Decision Criteria

The selected architecture must:

Provide public HTTPS.
Integrate with Azure Storage.
Support the approved hostname.
Support the required delivery/CDN behavior.
Fit the approved USD $40/month recurring Azure/cloud cost ceiling, with documented exclusions.
Be representable through source-controlled infrastructure where applicable.
Consequence

- The actual deployed Front Door SKU is Standard.
- The approved FreeDNS hostname resolves to Front Door.
- HTTPS is active with an Azure-managed certificate.
- HTTP redirects to HTTPS.
- Azure Storage is the origin.
- The deployed resources and measured/estimated billing remain within the approved $40/month ceiling.
- No paid domain registration is introduced.

## Freeze Gate

This ADR unblocks:

- Production delivery implementation.
- DNS configuration.
- Frontend CI/CD architecture.
- Production acceptance planning.

The production deployment remains gated by the remaining open requirements, especially OR-005 and any applicable P2 contract decisions.
