# ADR-007 — Visitor Counting Semantics

## Status

Pending approval

## Requirement Addressed

- REQ-AZ-007
- REQ-AZ-008
- REQ-AZ-009
- REQ-AZ-015

## Problem

The term "visitor" is not currently defined sufficiently to determine exactly when the persistent counter should increment.

Possible interpretations include:

1. Every page load.
2. Every API request.
3. Every browser session.
4. Every unique visitor.
5. Another explicitly approved unit.

## Current Architectural Constraint

The implementation must not invent counting semantics.

The API, data model, tests, and frontend behavior must follow the selected definition.

## Decision Criteria

The selected definition must be:

- Objectively testable.
- Consistent with the public visitor-counter requirement.
- Compatible with a privacy-preserving implementation.
- Implementable without introducing unrelated analytics functionality.
- Persistent through normal deployments.

## Consequences

This decision affects:

- JavaScript behavior.
- API contract.
- Database update behavior.
- Concurrency handling.
- Automated tests.
- Acceptance testing.

## Freeze Gate

The counting unit must be approved before implementing the visitor-counter persistence/update logic.
