# ADR-007 — Visitor Counting Semantics

## Status

Accepted

## Requirement Addressed

- REQ-AZ-007
- REQ-AZ-008
- REQ-AZ-009
- REQ-AZ-015

## Decision

Define a visitor as one successfully committed visitor-counter API operation caused by a top-level resume page load.

The frontend performs exactly one counter request per top-level resume page load. A refresh is therefore another visit.

The counter does not identify unique humans, browsers, sessions, IP addresses, devices, or users.

Failed API/database operations do not increment the persisted count.

## Concurrency Rule

The backend must perform an atomic/concurrency-safe increment. Concurrent successful operations must not overwrite each other's increments.

If the persisted value is N, then K successfully committed counter operations must result in N + K.

## Decision Criteria

The selected definition must be:

- Objectively testable.
- Consistent with the public visitor-counter requirement.
- Compatible with a privacy-preserving implementation.
- Implementable without introducing unrelated analytics functionality.
- Persistent through normal deployments.

## Consequences

This decision affects:

- JavaScript behavior.
- API contract.
- Database update behavior.
- Concurrency handling.
- Automated tests.
- Acceptance testing.

## Acceptance

The visitor semantics are deterministic, privacy-preserving, compatible with static hosting, and directly testable. Implementation, API contract, persistence logic, and tests must use this definition.
