# ADR-008 — Azure Functions Flex Consumption Hosting

## Status
**Accepted — current hosting decision**

## Context
The project previously approved Azure Functions Linux Consumption hosting using the Y1 / Dynamic plan.

The previous deployment attempt failed because the Azure subscription had a Y1 VM quota of 0. The attempted quota increase to 1 was unsuccessful.

The project owner explicitly prohibited further Y1 quota-increase workarounds and approved a change to Azure Functions Flex Consumption.

## Decision
The current Functions hosting baseline is:
- Azure Functions Flex Consumption.
- Linux.
- Functions runtime v4.
- Python 3.12.
- Flex Consumption SKU: FC1.
- Serverless scale-to-zero behavior.
- Always-ready instances: 0 for the MVP.
- System-assigned managed identity.
- Azure Cosmos DB for Table API.
- Cosmos DB serverless capacity.
- ARM as Infrastructure as Code.
- GitHub Actions for CI/CD.
- Microsoft Entra OIDC for deployment authentication.

## Before / After
| Area | Previous | Current |
|---|---|---|
| Functions hosting | Linux Consumption / Y1 | Flex Consumption |
| Hosting SKU/model | Y1 Dynamic | FC1 / FlexConsumption |
| Scale model | Serverless | Serverless |
| Always-ready | N/A | 0 for MVP |
| Long-term platform | Legacy / retirement risk | Current approved model |
| Quota dependency | Y1 VM quota | Flex Consumption quota model |

## Rationale
The change removes the blocked Y1 quota dependency and aligns the project with the current Azure Functions serverless hosting direction. Microsoft documentation identifies Flex Consumption as a current serverless hosting model capable of scaling to zero and provides ARM configuration using Microsoft.Web/serverfarms with FC1 / FlexConsumption and Microsoft.Web/sites.functionAppConfig. citeturn0search6turn1search3

Python 3.12 is supported on Flex Consumption in current Azure Functions runtime metadata. citeturn0search8

## Consequences
### Positive
- Removes dependency on the unavailable Y1 VM quota.
- Uses the approved current Flex Consumption hosting model.
- Preserves serverless scale-to-zero behavior.
- Keeps the MVP at zero always-ready instances.
- Retains the existing API, Cosmos DB, managed identity, ARM, and GitHub Actions boundaries.

### Required Follow-up
Phase 1 must update:
- ARM hosting-plan resource.
- Function App Flex functionAppConfig.
- Flex deployment storage/container configuration.
- Identity-based storage configuration required by Flex.
- Function packaging/deployment workflow as required by Flex.
- IaC tests.
- Deployment validation documentation.
- Configuration inventory entries affected by Flex.
- Hosting-specific acceptance and test cases.

Flex Consumption requires a deployment storage container and supports managed-identity-based deployment storage configuration. These are implementation requirements for the Phase 1 ARM update, not Phase 0 implementation work. citeturn1search0turn1search10

## Historical Evidence
The failed Y1 deployment is historical evidence:
- Resource: Microsoft.Web/serverfarms/sixteen-resume-functions
- Previous model: Linux Consumption / Y1
- Subscription Y1 VM quota: 0
- Requested quota increase: 1
- Quota increase result: unsuccessful
- Current action: do not retry Y1 quota increase

## Reversibility
The decision can be reversed only through an explicit architectural change approval. Reverting to Y1 is not an acceptable implementation workaround for the current project state.
