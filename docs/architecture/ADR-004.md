# ADR-004 — ARM and GitHub Actions Deployment Architecture

## Status

Accepted

## Requirement Addressed

- REQ-AZ-011
- REQ-AZ-012
- REQ-AZ-013
- REQ-AZ-014
- REQ-AZ-DEV-001
- REQ-AZ-GIT-001

## Decision

Use:

- ARM templates for Azure infrastructure.
- GitHub Actions for CI/CD.
- Separate frontend/backend repositories.
- `develop` for integration.
- `main` for production.

Backend CI must execute tests before production deployment.

Frontend CI publishes approved production changes to Azure Storage.

## Alternatives Considered

### Manual Azure Portal deployment

Rejected because production infrastructure must be source-controlled and reproducible.

### Terraform/Bicep

Rejected because ARM is the approved IaC format.

### Single repository

Rejected because separate frontend/backend repositories are part of the approved requirements.

### Manual production deployment

Rejected because automated CI/CD is required.

## Trade-offs

Advantages:

- Reproducibility.
- Auditability.
- Automated testing.
- Clear separation of responsibilities.

Trade-offs:

- More repository/workflow configuration.
- CI/CD credentials require careful security design.

## Consequences

Production infrastructure and application deployment become pipeline-driven.
